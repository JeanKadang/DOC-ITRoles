# Security Policy

## Supported Versions

Security fixes are provided for the current released version of this repository.

| Version | Supported |
| ------- | --------- |
| 1.4.x   | Yes       |
| < 1.4   | No        |

## Reporting a Vulnerability

Report suspected vulnerabilities privately to the primary maintainer:

- Primary maintainer: Jean Kadang (`@JeanKadang`)

Use an established private contact channel for the maintainer. Do not open a
public GitHub issue or discussion with exploit details, credentials, private
repository content, or other sensitive information.

If additional maintainers are invited to the project, this section should be
updated with the current security contact list.

## What To Include

Please include enough detail to reproduce and assess the issue:

- A short description of the vulnerability and affected area.
- Steps to reproduce, proof of concept, or affected files where appropriate.
- The expected impact.
- Any known workaround or mitigation.

## Response Expectations

The maintainer will acknowledge valid reports as soon as practical, triage the
impact, and coordinate remediation before public disclosure. If the report is
not considered a security vulnerability, the maintainer will explain why and may
redirect the issue to the normal GitHub issue tracker.

## Scope

Security reports should focus on risks such as exposed secrets, unsafe
execution paths, dependency or workflow supply-chain issues, authorization
problems, or vulnerabilities in the local web viewer. General content
corrections, role taxonomy changes, documentation improvements, and feature
requests should be filed as normal GitHub issues.
